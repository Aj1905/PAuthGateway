## 証拠

- [ ] 中心的主張ごとに、原データまたは再現可能な結果がある。
- [ ] 実装、評価文書、既存原稿の不一致を確認した。
- [ ] 結果ファイルの形式版、生成日時、ソース状態を確認した。
- [ ] 未追跡または古い成果物を確定結果として扱っていない。
- [ ] 他の論文原稿や別条件の実験を混ぜていない。
- [ ] 引用する論文とソフトウェアの版を固定した。

## 用語と定義

- [ ] `AGENTS.md` と `docs/SYSTEM_MODEL.md` の現行内容を読んだ。
- [ ] PAuth 固有、論文固有、馴染みの薄い専門概念をすべて抽出した。製品、モデル、ベンチマーク、統計検定、略語も確認した。
- [ ] 正本にない専門概念を本文より先に正本へ追加した。
- [ ] 各専門語の初出で、一般語による定義を書いた。
- [ ] 定義文の中に未定義専門語がない。
- [ ] 地の文の日本語名、コード識別子、図中の英語名を使い分けた。
- [ ] ノード、成果物、実行部、結合境界を混同していない。
- [ ] DSL の版、ツール呼び出し、失敗語彙、現行指標名が正確である。

## 「はじめに」

- [ ] 最初の具体例が研究課題へ直接つながる。
- [ ] 既存方式の限界を対象と粒度で説明した。
- [ ] 着想の根拠が記録または著者確認にある。
- [ ] 必要性を、放置した場合の具体的な失敗で説明した。
- [ ] 研究上の問いが評価設計と一致する。
- [ ] 貢献を実装、測定、知見に分け、先行研究の再実装を新規提案と呼んでいない。
- [ ] 事故例から防止効果へ飛躍していない。

## 結果

- [ ] 各比較に基準実装と変更内容がある。
- [ ] 指標の定義、分母、条件、試行数がある。
- [ ] 前値、後値、件数差、割合の差が一致する。
- [ ] 改善した事例を具体的な実装差まで分解した。
- [ ] 悪化、不変、失敗した介入も報告した。
- [ ] 対になる誤り方向と主目的指標を同時に示した。
- [ ] 条件付き診断を系全体の性能と呼んでいない。
- [ ] 対照条件なしで因果を断定していない。
- [ ] 結果節と考察節を分けた。
- [ ] 主張できない範囲を妥当性への脅威へ送った。

実験過程を説明する必要がある場合は、存在を確認した上で `tests/experiment/LOG.md` と `docs/GT_NO_MISSING_IMPROVEMENT_LOG.md` の「仮説、介入、複数指標、副作用、採否」という記録方法を参考にする。そこにある数値を現行結果とみなさない。

## 文章

- [ ] 各段落が一つの問いへ答える。
- [ ] 主語、行為者、対象が分かる。
- [ ] 抽象的な重要性を、事例、数値、制約へ置き換えた。
- [ ] 「本節では」「以下では」などの予告を削った。
- [ ] 「まず、次に、最後に」の定型列挙を崩した。
- [ ] 同じ文型、同じ長さ、同じ接続詞の連続を直した。
- [ ] 二項対立、三項列挙、短い決め台詞を演出のために使っていない。
- [ ] 「包括的」「画期的」「顕著」「重要」などの評価語に証拠がある。
- [ ] 読者が因果を追えるが、著者の心情や出来事を創作していない。

次の五項目を各 10 点で採点する。合計 40 点未満、または証拠の正確さが 8 点未満なら改稿する。

| 項目 | 10 点の状態 |
|---|---|
| 証拠の正確さ | すべての主要主張を原データへ追跡できる |
| 用語の明瞭さ | 初出定義だけで一般読者が後続を読める |
| 因果の連続 | 問題、着想、設計、評価、結果が飛躍なくつながる |
| 結果の透明性 | 利点、副作用、不変、限界を同じ基準で示す |
| 文章の自然さ | 定型句に頼らず、具体的な主語と変化で読ませる |

## 形式と再現性

- [ ] Markdown、LaTeX、BibTeX、図の参照が切れていない。
- [ ] 本文、表、図、要旨、結論の数値が一致する。
- [ ] LaTeX のビルドが通り、警告と PDF を確認した。
- [ ] Markdown は Markdown 自体を読み直した。
- [ ] 再現コマンド、依存版、モデル識別子、ソース状態を記録した。
- [ ] LLM 利用記録が実際の支援内容と一致する。
