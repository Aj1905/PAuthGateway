# Planner 戦略候補

## 本書の責務

本書は、未実装の Planner 戦略候補について、処理の流れ、導入条件、失敗要因を
比較する設計メモである。現行戦略の一覧、実装状態、既定値、設定方法は記録しない。

正本は次のとおり。

- 正準名と生成処理: `gateway/planning/planner.py` の `KNOWN_STRATEGIES` と
  `build_planner()`
- 現在の構成と Planner 境界: `ARCHITECTURE.md` §1.1、§2
- 配備時の設定: `gateway/hooks/README.md` §3
- 候補の採否と実装状態: `DESIGN_STATUS.md`「Planner 戦略の発展」

本書が扱う三候補は `DESIGN_STATUS.md` の状態表に対応する。実装時には `Planner`
契約に従って制限付き `run()` コードを返し、後段の GrammarValidator、Slicer、
Rule compiler へ渡す。候補がルールを直接生成してはならない。

## `interactive-structuring`

コード生成前に利用者へ確認し、不足しているオペランド、条件、ツール、日付、
数量、宛先を補う。確認結果を構造化した後、コード生成器へ渡す。

処理の流れ:

1. 利用者のプロンプトを受け取る。
2. 欠けた値と曖昧な条件に絞って質問する。
3. 回答から構造化プロンプトまたは意図オブジェクトを作る。
4. 構造化した入力をコード生成器へ渡す。
5. 生成コードを通常の PAuth パイプラインへ送る。

導入条件:

- ゲートウェイが、計画前の利用者向け対話を所有できること。
- 生のプロンプト、質問、回答、構造化結果、生成コードを監査ログへ残せること。

失敗要因:

- 質問範囲が広いと、利用者の回答にも曖昧さが残る。
- 構造化結果を監査できないと、誤った補完がコード生成前へ移るだけになる。
- 対話面を持たない配備では、この候補を利用できない。

## `specialized-codegen`

利用者のプロンプトとツールスキーマから、制限付き `run()` コードだけを生成する
専用モデルを用いる。GrammarValidator の文法棄却理由を再試行へ返す。

処理の流れ:

1. プロンプトと利用可能なツールスキーマをモデルへ渡す。
2. モデルが `def run(...): ...` を生成する。
3. GrammarValidator、Slicer、Rule compiler を実行する。
4. 文法棄却またはコンパイル失敗があれば、理由をモデルへ返す。
5. 再試行予算を使い切った場合は `PlanGenerationError` を返す。

導入条件:

- `prompt + tool schema -> restricted run() code` のレビュー済みデータを用意すること。
- 文法適合率と意図忠実性を別々に評価すること。
- 失敗した生成と検証結果を、再学習または評価用に保存すること。

失敗要因:

- 文法に適合しても、必要なツール呼び出しや条件を欠落させる場合がある。
- モックスイートのデータだけで訓練すると、実際の MCP ツールへ転移しない。
- 検証器は文法とコンパイル可能性を判定できるが、利用者の意図を証明できない。

## `formal-semantic`

受理する自然言語を制限し、構文解析と意味解析を経て制限付き `run()` コードへ
変換する。LLM を使う場合も、曖昧さの解消など限定した役割に留める。

処理の流れ:

1. 対象とするタスク言語を定義する。
2. プロンプトを形式文法で解析する。
3. 意味形式をツール、オペランド、guard、データ依存関係へ写像する。
4. 制限付き `run()` コードを生成する。
5. 生成コードを通常の PAuth パイプラインへ送る。

導入条件:

- 狭いタスク領域と受理する言語を明示すること。
- 言語の網羅率と、受理したタスクの正しさを別々に測定すること。
- 未知の表現を暗黙に補完せず、解析不能として扱うこと。

失敗要因:

- 実際のプロンプトが定義済み文法の外へ外れる。
- 例外規則を追加し続けると、文法を保守できなくなる。
- 曖昧さの解消を LLM に委ねると、形式解析の保証範囲が不明確になる。

## 更新規則

候補の採用、見送り、実装着手は `DESIGN_STATUS.md` に記録する。実装する PR は、
コード、本書、`ARCHITECTURE.md`、`gateway/hooks/README.md`、`DESIGN_STATUS.md` を
同時に更新する。実装した候補の節は、設計判断の履歴へ移すか削除する。本書には
現行戦略の一覧や設定例を追加しない。
