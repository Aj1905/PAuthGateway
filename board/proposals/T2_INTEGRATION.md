# T2 本番統合の具体案

状態: 確認部品の改善は実装・検査済み。本書の本番接続は未実装。
ユーザーが指定した `gateway/runtime/gateway.py` と `gateway/serving/mcp_facade.py`
の編集禁止は解除されていないため、この二つのファイルは変更していない。

## 達成する挙動

1. エージェントは読み取りと、信頼済みのオペランドだけを持つ書き込みを続けられる。
   未信頼データに依存する書き込みは、具体値入りのツール呼び出しとして集め、実行しない。
2. エージェントが「今回の読み取りを終えた」と明示した時点で、候補を固定する。
   固定後は候補を追加・変更せず、出所付きの全候補を運用者に一度に提示する。
3. 運用者は候補ごとに承認・却下を選ぶ。全候補の判断がそろうまで、対象の書き込みは実行しない。
4. ゲートウェイが承認済み候補だけを順に実行する。実行試行の耐久化、既定拒否、
   観測の署名、監査、結果不明時の再実行拒否は既存経路を使う。
5. エージェントには実行結果を返す。承認後に同じ副作用を二重実行しない。
   却下理由は値なし。新しい試みは新しい候補集合として同じ関門を通す。

「読み取り終了」の合図が必要なのは、現在の本番経路をエージェントが一手ずつ駆動しており、
ゲートウェイが勝手にその終了時点を仮定できないため。計画を提出しただけで
ゲートウェイが全処理を実行する方式へ、黙って変更しない。

## 接続するパスと役割

| パス | 変更 |
|---|---|
| `gateway/runtime/batched_confirmation.py` | 候補の収集・固定・個別判断・承認済み候補の実行を共有部品に分ける。既存の同期試作は同部品を使う互換入口として残す |
| `gateway/runtime/gateway.py` | `c2 + human` を受け付け、収集/確認/実行の状態を管理する。既存の実行・耐久化・監査を経由する |
| `gateway/ingress/agent_channel.py` | 読み取り終了と結果取得の制御メッセージを扱う |
| `gateway/serving/http_server.py` | 運用者専用の候補一覧・一括判断と状態取得を接続する。エージェント用トークンで判断を受け付けない |
| `gateway/serving/mcp_facade.py` | 保留時は他の読み取りを続けられると伝え、読み取り終了の合図と結果取得を公開する |
| `gateway/operator/cli.py` | 候補全体を一度に表示し、個別判断をまとめて提出する |
| `gateway/serving/session_store.py` | 未完了候補と判断状態を永続化し、再起動で承認範囲を失ったり広げたりしない |

`gateway/hooks/` の変更は予定しない。

## 統合完了を示す検査

- 未信頼読み取り1件から生じる書き込み2件が、判断前には実バックエンドに届かない。
- 候補一覧にツール名・すべての具体値・出所があり、片方承認/片方却下で承認分だけ一度実行する。
- 信頼済みの書き込みが返す値を使う後続の読み取りは、収集中に実行できる。
- 候補固定後の追加・引数変更、古い判断の再送、同一候補の並行実行を拒否する。
- エージェント用トークンによる承認、値を含む却下理由の還流を防ぐ。
- 承認後の再起動・実行中クラッシュで二重実行しない。
- 実MCPと実際の運用者の判断を使う試験で確認回数・実行回数を記録する。

この案の承認だけで上の検査や人間の実測を済んだことにはしない。
