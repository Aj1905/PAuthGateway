   試行錯誤してアプリを完成させること。途中で止めて許可を求めるのではなく、
   自律的に進める。
6. Claude Code と Codex の両方に同じ作業をさせる。両者は連携し合って進める。
7. 連携の手段は、実験用リポジトリ内の **共通の掲示板**(`board/`)。両者は

   進める。
8. 片方がもう片方を CLI で操作するような連携は不要。各自が自分で掲示板を
   読み書きして連携する。
9. **(2026-09-08 夕方の新指示・最優先)** いま一番やってほしいのは **Planner の部分**。
   なるべく汎用的なタスクに対して**最小権限を自動発行**できるように、LLM とその周りの

## 3. 作業規約(掲示板方式)

同じ作業ディレクトリ・同じブランチで二者が並行して作業するため、次を守る。

### 掲示板の構成

| ファイル | 役割 | 書く人 |
|---|---|---|
| `board/INSTRUCTIONS.md` | 依頼主の指示の写し(本文書) | 依頼主の新指示があったときのみ |
| `board/BOARD.md` | 現状の判断・方向性・タスク台帳・方向修正の記録 | 両者(小さな編集を、読み直してから行う) |
| `board/log-claude.md` | Claude Code の進捗記録(追記のみ) | Claude Code のみ |
| `board/log-codex.md` | Codex の進捗記録(追記のみ) | Codex のみ |

### 手順

1. **開始時**: `BOARD.md` を読み直す。台帳から着手するタスクを選び、担当欄に
   自分の名前、状態を「進行中」にしてから作業に入る(先に書いた者が担当)。
   新しいタスクが必要なら台帳に追加する。
2. **作業中**: 触るファイルはタスクごとに分離する。同じファイルを両者が同時に
   編集しない。相手が進行中のタスクのファイルには触らない。
3. **コミット**: `git add <自分の変更したパス>` で自分のファイルだけを stage する。
   `git add -A` / `git add .` は禁止。`git reset --hard`、`git checkout -- .`、
   `git stash`、ブランチ切替など、相手の作業ツリーの変更を消しうる操作は禁止。
   コミットメッセージの先頭に `[claude]` / `[codex]` を付ける。
4. **完了時**: 台帳の状態を「完了」にし、成果(何ができるようになったか、
   測った数値、残った問題)を自分の log に追記する。log は日付付きの箇条書きで、
   後から相手が読んで再現できる粒度にする。
5. **方向修正**: 「今の方向は違う」と判断したら、`BOARD.md` の「方向修正の
   記録」に日付・理由・新しい方向を書き、台帳を組み替える。相手の判断を
   上書きする場合は、理由を書く。黙って変えない。
6. **本体リポジトリには触らない**(`/Users/aj/Documents/AJ/PAuthGateway`)。
7. **検査を壊さない**: コミット前に自分の変更が関係する検査を通す。全検査は
   長い(約 2 分半)ので、関係する検査ファイルを先に、全検査は節目で回す。
8. **主張は測ってから書く**: 「実用に耐える」の判断は、掲示板に書いた基準
   (`BOARD.md` の「完成の判定基準」)に対する実測で示す。

## 4. 完成の定義(依頼主の言葉に基づく)

「エージェントにタスクを丸投げする安心感」が得られる状態。
安心感は主観なので、`BOARD.md` に測れる判定基準へ翻訳して置き、そこに照らして
両者が「達成した」と判断できたら完成とする。判定基準そのものも掲示板で
修正してよいが、目的の一文(上記 1-1)は変えない。
